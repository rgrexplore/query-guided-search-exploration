\section{Experiments}
\subsection{Setup}
Every run uses the same one million MS MARCO document embeddings~\cite{msmarco}, the same 200 query
embeddings, and the same reference answers. The embeddings were already produced with
Nomic~\cite{nomic}. We do not regenerate them, change their values, shorten them, or select different
queries for different methods.

The documents contain 256 sign bits; queries retain 256 floating-point values. The reference
answer is the best 100 document IDs from a full scoring calculation. A recall of 99\% means
returning 99 of those same 100 IDs on average. All methods use that identical reference.

Only the index parameters listed in Section 3 change: clusters, probes, B's leaf size and
branch budget, and C's key width and lookup limit. The complete score still uses all 256 bits.

For each cluster count, the code finds probe counts reaching 80\%, 90\%, 95\%, and 99\% recall
with the original scan. It also includes opening every cluster. These probe choices are
available to A, B and C. This avoids giving A an unnecessarily expensive probe count when
comparing it with a more selective method.

We measured 256 parameter settings in total.

The machine is an Apple M5 Max with 128 GiB of physical memory. Each process has a 32 GB
memory budget and uses one CPU thread. Every setting searches all 200 queries twice. The
fastest successful settings are then repeated in three processes, still using those same
queries. Reported time is the middle measurement, or median.

Retrieval time includes choosing clusters and searching their documents. It excludes
building the index and generating embeddings. File hashes for the document, query and
reference arrays are checked before and after the measurements.

The parameter sweep answers which tested settings were fastest on this unchanged dataset.
For A, increasing the recall requirement from 90\% to 99\% increases the opened clusters
from 353 to 2440, out of 8192. Its median time rises from 1.43 to 8.74 ms. The query vectors stay
the same; the extra work comes from opening more clusters.
These results concern this dataset and the tested parameter ranges.
