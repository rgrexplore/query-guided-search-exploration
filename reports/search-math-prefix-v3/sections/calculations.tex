\section{Preliminary calculations}

Before running the experiments, let’s first break down where each method actually spends its work.

The idea is simple. Method A scores every document inside the opened clusters. Method B tries to avoid some of those scores by filtering with Bitplanes first. Method C tries to avoid starting from a large set of documents at all by looking up a specific prefix and broadening it only when necessary.

So for each method, I mainly want to understand two things:

\textbf{What additional work does this method introduce, and how many full document scores can that work potentially save?}

I will use the same small example throughout this section and then generalize it into the formulas that we will later compare with the experiments.

Throughout this section:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.26\linewidth}p{.68\linewidth}@{}}
\toprule
Symbol & Meaning\\
\midrule
\(N\) & Total number of documents\\
\(C\) & Total number of clusters\\
\(P\) & Number of clusters opened for one query\\
\(d\) & Number of binary dimensions\\
\(K\) & Number of results we want to return\\
\(n_c\) & Number of documents inside cluster \(c\)\\
\(F_A,F_B,F_C\) & Number of documents that receive the full score under A, B and C\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


If the clusters are roughly balanced, one cluster contains about

\[
n \approx \frac{N}{C}
\]

documents.

So if we open \(P\) clusters, we expose roughly

\[
\frac{PN}{C}
\]

documents.

This is only an approximation for intuition. The experiments later use the actual number of documents inside the opened clusters.



\subsection{Query-time work}

Let’s use one tiny example so that we can see exactly what each method is doing.

Suppose one opened cluster contains three documents:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.16\linewidth}p{.42\linewidth}p{.34\linewidth}@{}}
\toprule
ID & Binary document & Full score\\
\midrule
0 & \texttt{10100} & 0.1\\
1 & \texttt{11001} & 2.5\\
2 & \texttt{11000} & 1.9\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


The query is

\[
q=[0.7,\ 0.5,\ -0.4,\ -0.6,\ 0.3].
\]

From the previous section, we know that the ideal binary document is

\texttt{11001}

and suppose we want the best

\[
K=2
\]

documents.

For this example:

\[
N=3,\qquad C=P=1,\qquad d=5.
\]

The example is intentionally small. The actual experiments later contain hundreds of thousands or millions of documents.



\subsubsection{Method A: scan the opened clusters}

Method A is the easiest one to understand.

Once cluster selection has decided which clusters to open, \textbf{every document inside those clusters receives the full score}.

\Needspace{4\baselineskip}
\textbf{Step 1: how many documents do we need to score?}\par

In our example, the only opened cluster contains:

\texttt{[ID 0, ID 1, ID 2]}

so:

\[
F_A=3.
\]

More generally, let \(O\) be the set of clusters opened for one query. Then:

\[
\boxed{
F_A=\sum_{c\in O}n_c
}
\]

is the number of documents A fully scores.

If the clusters are roughly balanced:

\[
F_A\approx\frac{PN}{C}.
\]

So for A, this is already the most important number: \textbf{how many documents did cluster selection leave for us to search?}

\centering
\begin{tikzpicture}

\node[scan,text width=24mm] (p) at (29mm,0) {Select $P$\\clusters};
\node[scan,text width=29mm] (rows) at (65mm,0) {$F_A$ documents\\\texttt{10100}\\\texttt{11001}\\\texttt{11000}};

\caption{Method A performs no additional filtering after cluster selection. Every document inside the opened clusters receives the full score.}
\end{figure}





\Needspace{4\baselineskip}
\textbf{Step 2: what does one full score cost?}\par

The scorer used here follows the four-sign lookup-table approach described in Exa’s article.

Instead of multiplying every query value with every document bit individually, the query is divided into groups of four.

For our five-dimensional example:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
[0.7, 0.5, -0.4, -0.6]\\ \relax [0.3, 0, 0, 0]
\end{tabular}\endgroup\end{center}

A four-bit group has

\[
2^4=16
\]

possible binary patterns.

So this example needs

\[
2\times16=32
\]

precomputed table entries.

In general, the number of groups is

\[
G=\left\lceil\frac d4\right\rceil.
\]

One document score therefore reads \(G\) table entries.

For our example:

\[
G=2.
\]

Three documents therefore require:

\[
3\times2=6
\]

table lookups.

In general, the scoring work grows with

\[
F_AG.
\]

Since \(G\) grows with \(d\),

\[
T_{\text{score},A}=O(F_Ad).
\]

For a fixed binary dimension, this is basically linear in the number of documents we score.



\Needspace{4\baselineskip}
\textbf{Step 3: keep only the best K}\par

As scores are produced, we only need to keep the best \(K\).

For our example:

\begin{center}\begin{tikzpicture}
\node[scan,text width=30mm] (a) at (0,0) {ID 0: 0.1};
\node[scan,text width=30mm] (b) at (46mm,0) {ID 1: 2.5\\ID 0: 0.1};
\node[scan,text width=30mm] (c) at (92mm,0) {ID 1: 2.5\\ID 2: 1.9};
\draw[arr](a)--(b);\draw[arr](b)--(c);
\end{tikzpicture}\end{center}

Using a bounded heap, maintaining the best \(K\) results takes at most approximately

\[
O(F_A\log(K+1)).
\]



\Needspace{4\baselineskip}
\textbf{Total cost for A}\par

Let \(T_{\text{base}}\) contain the work before full document scoring, such as cluster selection and score-table preparation.

Let \(a_A\) be the average measured time needed to fully process one document, including its score and the top-\(K\) update.

Then:

\[
\boxed{
T_A\approx T_{\text{base}}+F_Aa_A.
}
\]

For roughly balanced clusters:

\[
\boxed{
T_A\approx
T_{\text{base}}
+
\frac{PN}{C}a_A.
}
\]

The main tradeoff is straightforward.

Using more clusters usually makes each cluster smaller, so each opened cluster contains fewer documents. However, we may then need to open more clusters to maintain the same recall.

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- Method A:} A’s cost is mainly determined by how many documents cluster selection leaves behind. Fewer opened documents means fewer full scores, but opening too few clusters can hurt recall.}}\end{center}



\subsubsection{Method B: Bitplanes}

Bitplanes try to reduce the number of documents that receive the full score.

Instead of immediately scoring every document inside the opened clusters, B first uses Bitplanes to filter the documents.

So B has two main costs:

\[
\boxed{
\text{Bitplane work}
+
\text{full scoring of the documents that survive}
}
\]

The whole idea only makes sense if the full scores we avoid are more expensive than the Bitplane work required to avoid them.



\Needspace{4\baselineskip}
\textbf{Step 1: inspect the important query bits first}\par

B uses the same cluster selection and the same full-score table as A.

The additional step is to order the query bits by decreasing \(|q_i|\).

For

\[
q=[0.7,\ 0.5,\ -0.4,\ -0.6,\ 0.3],
\]

the order is:

\begin{center}\begin{tikzpicture}
\foreach \i/\bit/\weight in {0/1/0.7,1/4/0.6,2/2/0.5,3/3/0.4,4/5/0.3} {
\node[branch,text width=19mm] (b\i) at (\i*29mm,0) {Bit \bit\\(\weight)};
}
\foreach \i/\j in {0/1,1/2,2/3,3/4} {\draw[arr](b\i)--(b\j);}
\end{tikzpicture}\end{center}

We inspect the larger values first because mismatching them hurts the score more.

Sorting these positions costs

\[
O(d\log d).
\]

We also calculate the ideal score:

\[
Q=\sum_i|q_i|=2.5.
\]

\centering
\begin{tikzpicture}

\node[scan,text width=30mm] (p) at (0,0) {Select $P$ clusters};
\node[branch,text width=56mm] (o) at (54mm,0) {Order bits by $|q_i|$\\$1\to4\to2\to3\to5$};

\end{tikzpicture}
\caption{Bitplanes keep the same cluster-selection stage as A, but add query-dependent filtering before the full scorer.}
\end{figure}





\Needspace{4\baselineskip}
\textbf{Step 2: represent the documents using a mask}\par

Inside one cluster, B keeps a bitmap showing which document positions are still active.

If cluster \(c\) contains \(n_c\) documents, its mask needs

\[
\boxed{
W_c=
\left\lceil
\frac{n_c}{64}
\right\rceil
}
\]

64-bit machine words.

Our three-document example fits inside one word.

The starting mask is:

\texttt{111}

which means that all three documents are still active.



\Needspace{4\baselineskip}
\textbf{Step 3: split using the query bits}\par

The first query position is bit 1, and the query prefers \texttt{1}.

All three documents match:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
111 AND 111 = 111
\end{tabular}\endgroup\end{center}

so nothing is removed.

The next position is bit 4. The query prefers \texttt{0}, and again all three documents match.

So the mask is still:

\texttt{111}.

The next position is bit 2.

Its Bitplane is:

\texttt{011}.

Therefore:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
111 AND 011 = 011
\end{tabular}\endgroup\end{center}

The preferred branch now contains IDs 1 and 2.

The alternative branch is:

\texttt{100}

which contains ID 0.

Because ID 0 disagrees with the query at bit 2, this branch has mismatch penalty:

\[
p=|q_2|=0.5.
\]

\centering

\end{figure}





\Needspace{4\baselineskip}
\textbf{Step 4: why Bitplane filtering is not free}\par

At first, a bitwise AND sounds almost free.

But that is only true for one machine word.

Suppose one cluster contains:

\[
6,400
\]

documents.

One mask then needs:

\[
6400/64=100
\]

machine words.

So one split does not perform one AND. It loops across roughly 100 word positions.

There is another important detail: \textbf{the mask does not physically get shorter when fewer documents remain active.}

For example, suppose only 80 documents survive after several splits.

The mask can still be 100 words wide.

So another split may still need to scan all 100 words.

\caption{The number of active documents can become much smaller while the physical bitmap stays the same size.}
\end{figure}



This is the main cost that B introduces.



\Needspace{4\baselineskip}
\textbf{Step 5: count the Bitplane work}\par

Let \(J_c\) be the number of times B splits a mask in cluster \(c\).

Each split scans \(W_c\) words.

So the total amount of split-mask work is:

\[
\boxed{
V_{\text{split}}
=
\sum_{c\in O}J_cW_c.
}
\]

For roughly balanced clusters, if B performs an average of \(S\) splits per opened cluster:

\[
V_{\text{split}}
\approx
PS
\left\lceil
\frac{N}{64C}
\right\rceil.
\]



\Needspace{4\baselineskip}
\textbf{Step 6: eventually stop splitting and score the documents}\par

B does not split forever.

Once a branch contains few enough documents, it becomes a \textbf{leaf}, and B fully scores the documents inside it.

Suppose our leaf size is two.

The preferred branch:

\texttt{011}

contains exactly IDs 1 and 2.

So B calculates:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
ID 1 \(\rightarrow\) 2.5\\ \relax ID 2 \(\rightarrow\) 1.9
\end{tabular}\endgroup\end{center}

Therefore:

\[
F_B=2.
\]

Method A would have scored all three documents.



\Needspace{4\baselineskip}
\textbf{Leaf masks still need to be read}\par

Before B can extract the surviving document positions, it still has to scan the leaf mask.

Let \(H_c\) be the number of leaf masks read in cluster \(c\).

Then:

\[
\boxed{
V_{\text{leaf}}
=
\sum_{c\in O}H_cW_c.
}
\]

I keep split-mask work and leaf-mask work separate because the implementation measures both separately.



\Needspace{4\baselineskip}
\textbf{Step 7: can we skip the waiting branch?}\par

ID 0 is still waiting.

Its known mismatch penalty is:

\[
p=0.5.
\]

The best possible score inside that branch is:

\[
Q-2p
=
2.5-2(0.5)
=
1.5.
\]

Our current top two scores are:

\[
2.5,\qquad1.9.
\]

Since:

\[
1.5<1.9,
\]

nothing inside the waiting branch can enter the current top two.

So B can safely skip it.

\centering
\begin{tikzpicture}

\node[box,draw=gray!65,fill=gray!7,dashed,text width=49mm,minimum height=24mm] (wait) at (0,0) {Waiting branch\\penalty = 0.5\\best possible score = 1.5};
\node[branch,text width=35mm,minimum height=24mm] (best) at (82mm,0) {Current top-2\\2.5\\1.9};
\draw[arr] (wait)--node[above,font=\small]{$1.5<1.9$}(best);

\end{tikzpicture}
\caption{Once the best possible score of a branch falls below the current top-\(K\) threshold, the whole branch can be skipped.}
\end{figure}





\Needspace{4\baselineskip}
\textbf{Total cost for B}\par

B therefore pays for:

\begin{itemize}\setlength{\itemsep}{1pt}
\item ordering the query bits;
\item reading split masks;
\item reading leaf masks;
\item maintaining the waiting branches;
\item fully scoring \(F_B\) documents.
\end{itemize}

Let:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.26\linewidth}p{.68\linewidth}@{}}
\toprule
Symbol & Meaning\\
\midrule
\(b_s\) & Average time for one split-mask word\\
\(b_l\) & Average time for one leaf-mask word\\
\(T_{\text{order}}\) & Ordering query bits and preparing query weights\\
\(T_{\text{queue}}\) & Managing branches, masks and the priority queue\\
\(a_B\) & Average time to fully process one surviving document\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


Then:

\[
\boxed{\begin{aligned}T_B\approx{}&T_{\text{base}}+T_{\text{order}}+b_sV_{\text{split}}+b_lV_{\text{leaf}}\\&+F_Ba_B+T_{\text{queue}}.\end{aligned}}
\]

The key condition is:

\[
\boxed{
\text{full-score work avoided}
>
\text{Bitplane work added}.
}
\]

A smaller leaf size may reduce \(F_B\), because B keeps filtering longer. However, that also means more splits and more bitmap work.

A larger node budget can also improve recall, but again it allows B to search more branches.

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- Bitplanes:} B is useful when a relatively small amount of bitmap work can eliminate a large number of full document scores. Scoring fewer documents alone is not enough; the bitmap work also has to be cheap enough.}}\end{center}



\subsubsection{Method C: Backward Walk}

Backward Walk starts from the opposite direction.

A begins with every document inside the opened clusters.

B also starts with all of them, then progressively removes documents.

C instead starts from a \textbf{very specific query prefix} and progressively broadens it only when necessary.

So C mainly pays for:

\[
\boxed{
\text{prefix lookups}
+
\text{full scoring of the documents that become visible}
}
\]



\Needspace{4\baselineskip}
\textbf{Step 1: store the documents in prefix order}\par

Using the same example, sort the documents by their binary key:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.16\linewidth}p{.42\linewidth}p{.34\linewidth}@{}}
\toprule
Position & Binary key & ID\\
\midrule
0 & \texttt{10100} & 0\\
1 & \texttt{11000} & 2\\
2 & \texttt{11001} & 1\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


The query's ideal binary key is:

\texttt{11001}.



\Needspace{4\baselineskip}
\textbf{Step 2: start from the most specific prefix}\par

Suppose C starts using all five bits.

It first searches for:

\texttt{11001}.

Because the documents are sorted, two binary searches find the beginning and end of this prefix range.

The result is:

\texttt{[2,3)}

which contains only ID 1.

So C scores:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
ID 1 \(\rightarrow\) 2.5
\end{tabular}\endgroup\end{center}

We need two results, so C continues.



\Needspace{4\baselineskip}
\textbf{Step 3: broaden the prefix}\par

C removes one prefix constraint:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
11001\\ \relax   \(\downarrow\)\\ \relax 1100*
\end{tabular}\endgroup\end{center}

The new range is:

\texttt{[1,3)}

which contains IDs 2 and 1.

ID 1 was already scored.

So C only needs to score the newly added document:

\texttt{ID 2 \(\rightarrow\) 1.9}.

Now C has two results.

\centering

\caption{A broader prefix already contains the documents found at the previous depth, so only the newly exposed rows need to be scored.}
\end{figure}



This is important because C does not rescore the same documents every time the prefix becomes shorter.



\Needspace{4\baselineskip}
\textbf{Step 4: how many prefix lookups do we perform?}\par

Let:

\begin{itemize}\setlength{\itemsep}{1pt}
\item \(x\): starting prefix depth;
\item \(\ell\): depth where C finally stops.
\end{itemize}

Then the number of depths visited is:

\[
L=x-\ell+1.
\]

Depth zero represents the entire cluster, so there is no prefix lookup there.

Let \(L_+\) be the number of visited depths above zero.

At each positive depth, C performs two boundary searches in each opened cluster:

\begin{itemize}\setlength{\itemsep}{1pt}
\item one to find the start of the matching prefix;
\item one to find the end.
\end{itemize}

Therefore the number of binary-search calls is:

\[
\boxed{
2PL_+.
}
\]

For cluster \(c\), each search costs approximately:

\[
O(\log(n_c+1)).
\]

So the lookup work is approximately:

\[
\boxed{
2L_+
\sum_{c\in O}
\log_2(n_c+1).
}
\]



\Needspace{4\baselineskip}
\textbf{Step 5: how many documents end up receiving the full score?}\par

Let:

\[
F_C
\]

be the total number of distinct documents exposed before C stops.

Because every broader prefix contains the previous range, each document is scored at most once.

So the full-score part is simply:

\[
F_Ca_C.
\]

This means the most important question for C is:

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{How broad does the prefix have to become before we have enough useful documents?}}}\end{center}



\Needspace{4\baselineskip}
\textbf{Step 6: how quickly does a prefix grow?}\par

For a simple intuition, temporarily assume that every bit is:

\begin{itemize}\setlength{\itemsep}{1pt}
\item independent;
\item equally likely to be \texttt{0} or \texttt{1}.
\end{itemize}

Then a prefix of length \(\ell\) matches one random document with probability:

\[
2^{-\ell}.
\]

So in a cluster with \(n\) documents, the expected number of matches is:

\[
\frac{n}{2^\ell}.
\]

Across \(P\) roughly balanced clusters:

\[
\boxed{
E[F_\ell]
\approx
\frac{PN}{C2^\ell}.
}
\]

For one global collection of one million documents:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.26\linewidth}p{.68\linewidth}@{}}
\toprule
Prefix depth & Expected matching documents\\
\midrule
16 & about 15\\
15 & about 31\\
14 & about 61\\
13 & about 122\\
12 & about 244\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


So removing one prefix bit roughly doubles the number of matching documents under this simplified model.

This is only an intuition for \textbf{how many documents} a prefix may contain.

It is not a recall estimate.

Real embedding bits can be correlated, and the distribution can change further once the documents have been divided into clusters.



\Needspace{4\baselineskip}
\textbf{Step 7: when should C stop?}\par

There are two possible stopping rules.

\Needspace{4\baselineskip}
\textbf{Approximate stopping}\par

The simplest rule is:

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{stop once at least \(M\) documents have been found.}}\end{center}

For example:

\begin{center}\begin{tikzpicture}
\foreach \i/\depth/\count in {0/16/12,1/15/31,2/14/66,3/13/136} {
\node[keys,text width=28mm] (b\i) at (\i*37mm,0) {\depth-bit prefix\\\count\ docs};
}
\foreach \i/\j in {0/1,1/2,2/3} {\draw[arr](b\i)--(b\j);}
\end{tikzpicture}\end{center}

If our target is 100 documents, we stop at 13 bits.

This is cheap, but it does \textbf{not} prove that a better document does not exist outside that prefix.

So this version can lose recall.



\Needspace{4\baselineskip}
\textbf{Exact stopping inside the opened clusters}\par

We can also use the score equation to prove that no unseen document can beat the current results.

Suppose C has fully searched a prefix of length \(\ell\).

Any unseen document must disagree with the query on at least one of those first \(\ell\) bits.

The cheapest possible mismatch is:

\[
m_\ell
=
\min_{1\le i\le\ell}|q_i|.
\]

Therefore the highest possible score of any unseen document is:

\[
\boxed{
U_\ell
=
Q-2m_\ell.
}
\]

Let \(\tau\) be the worst score currently inside the top-\(K\).

If:

\[
\boxed{
\tau>U_\ell,
}
\]

then no unseen document inside the opened clusters can enter the result.

C can stop safely.

If that never happens, C can keep relaxing the prefix until depth zero, where it has exposed every document inside the opened clusters.

At that point C becomes equivalent to A locally.



\Needspace{4\baselineskip}
\textbf{Total cost for C}\par

Let:

\begin{center}
\begin{minipage}{\linewidth}
\small
\renewcommand{\arraystretch}{1.2}
\begin{tabular}{@{}p{.26\linewidth}p{.68\linewidth}@{}}
\toprule
Symbol & Meaning\\
\midrule
\(T_{\text{key}}\) & Preparing the query prefix and score-bound data\\
\(t_b\) & Average time for one binary-search comparison\\
\(T_{\text{ranges}}\) & Updating prefix ranges and identifying new rows\\
\(a_C\) & Average time to fully process one exposed document\\
\bottomrule
\end{tabular}
\end{minipage}
\end{center}


Then:

\[
\boxed{\begin{aligned}T_C\approx{}&T_{\text{base}}+T_{\text{key}}+2L_+t_b\sum_{c\in O}\log_2(n_c+1)\\&+F_Ca_C+T_{\text{ranges}}.\end{aligned}}
\]

The key condition is:

\[
\boxed{
\text{full-score work avoided}
>
\text{prefix lookup work added}.
}
\]

If C can stop at a deep prefix, then:

\[
F_C\ll F_A
\]

and it may save a lot of scoring work.

But if C has to relax all the way to depth zero:

\[
F_C=F_A,
\]

so it does all of A’s scoring \textbf{plus} the additional prefix lookups.

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- Backward Walk:} C works best when a fairly specific query prefix already contains the documents we need. If it has to keep broadening until almost the whole cluster is visible, then the prefix index does not help.}}\end{center}

\subsection{Memory}

Query time is not the only cost.

B and C also require additional index structures, so we need to understand how much memory each method stores.

There are two useful categories:

\textbf{Persistent index memory} is built before queries arrive and remains loaded.

\textbf{Temporary query memory} only exists while one query is running.



\subsubsection{Method A}

A stores:

\begin{itemize}\setlength{\itemsep}{1pt}
\item one packed binary code per document;
\item one document ID per document;
\item the cluster/routing information.
\end{itemize}

With 64-bit words, one binary code occupies:

\[
8
\left\lceil
\frac d{64}
\right\rceil
\]

bytes.

An ID occupies 8 bytes.

So the document rows use:

\[
\boxed{
M_{A,\text{rows}}
=
N
\left(
8\left\lceil\frac d{64}\right\rceil+8
\right).
}
\]

The router uses additional memory.

For example, \(C\) float32 centroids of routing dimension \(d_R\) use approximately:

\[
4Cd_R
\]

bytes, plus their labels, offsets and implementation overhead.

During one query, A also keeps:

\begin{itemize}\setlength{\itemsep}{1pt}
\item the floating-point query;
\item the score table;
\item the current top-\(K\);
\item small routing state.
\end{itemize}

This is the baseline memory that B and C build on.



\subsubsection{Method B}

B keeps everything A stores.

It additionally stores:

\begin{enumerate}\setlength{\itemsep}{1pt}
\item the Bitplanes;
\item the temporary branch masks used during search.
\end{enumerate}

\Needspace{4\baselineskip}
\textbf{Stored Bitplanes}\par

One Bitplane in cluster \(c\) uses \(W_c\) words.

There are \(d\) Bitplanes.

Therefore:

\[
\boxed{
M_{\text{planes}}
=
8d
\sum_{c=1}^{C}W_c.
}
\]

The ceiling in \(W_c\) matters because every cluster has its own word padding.



\Needspace{4\baselineskip}
\textbf{Temporary branch masks}\par

Every active or waiting branch has its own mask.

For cluster \(c\), one mask uses:

\[
8W_c
\]

bytes.

If several branches are waiting, several full-width masks can be alive at the same time.

If \(A_c(t)\) masks from cluster \(c\) are alive at time \(t\), then the raw peak mask memory is:

\[
\boxed{
Q_{\text{masks}}
=
8
\max_t
\sum_c
A_c(t)W_c.
}
\]

The priority queue and node information require additional memory.

\centering
\begin{tikzpicture}

\node[box,text width=38mm,minimum height=35mm] (stored) at (0,0) {\textbf{Stored once}\\Packed documents\\IDs\\Bitplanes};
\node[box,text width=38mm,minimum height=35mm] (common) at (47mm,0) {\textbf{Common query}\\Query\\Score table\\Top $K$};
\node[branch,text width=42mm,minimum height=35mm] (masks) at (96mm,0) {\textbf{B-specific query}\\\phantom{Mask}\\\phantom{Mask}\\\phantom{Mask}\\$\cdots$};

\end{tikzpicture}
\caption{B stores an additional Bitplane layout and can also keep several full-width masks alive during one query.}
\end{figure}



\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- B memory:} B uses more persistent memory because it stores the bits twice: once by document and once as Bitplanes. Its main temporary-memory cost comes from the masks of waiting branches.}}\end{center}



\subsubsection{Method C}

C also keeps A's binary documents and IDs.

The current implementation additionally stores one 32-bit prefix key per document.

So:

\[
\boxed{
M_{\text{prefix}}=4N.
}
\]

The documents are sorted once by this key inside each cluster.

Importantly, C does \textbf{not} store a new copy of the documents for every prefix length.

The same sorted rows support:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
11001\\ \relax 1100*\\ \relax 110**\\ \relax 11***\\ \relax ...
\end{tabular}\endgroup\end{center}

by using different ranges.

So its temporary search state is relatively small compared with B.

\subsection{Recall}

So far we have only talked about speed.

But avoiding work is only useful if we still return the correct documents.

For query \(q\), let:

\begin{itemize}\setlength{\itemsep}{1pt}
\item \(G_q\) be the exact global top-\(K\) document IDs;
\item \(O_{a,q}\) be the IDs returned by method \(a\).
\end{itemize}

Then average recall is:

\[
\boxed{
R_a
=
\frac{
\sum_q
|G_q\cap O_{a,q}|
}{
n_qK
}.
}
\]

For example:

\begin{center}\begingroup\small\ttfamily\begin{tabular}{l}
Reference:\\ \relax [1, 2]\\ \relax Returned:\\ \relax [1, 0]
\end{tabular}\endgroup\end{center}

recovers one out of two:

\[
Recall=50\%.
\]



\Needspace{4\baselineskip}
\textbf{Where can recall be lost?}\par

There are actually two stages where a correct document can disappear.

\begin{figure}[htbp]
\centering
\begin{tikzpicture}

\node[box,text width=65mm] (global) at (0,0) {Global exact top-$K$};
\node[box,text width=90mm] (opened) at (0,-24mm) {Correct documents inside opened clusters};
\draw[arr] (global)--node[right,font=\small]{cluster selection}(opened);
\node[scan,text width=35mm,minimum height=23mm] (a) at (-49mm,-56mm) {\textbf{A}\\scan\\no local loss};
\node[branch,text width=35mm,minimum height=23mm] (b) at (0,-56mm) {\textbf{B}\\Bitplanes\\may stop early};
\node[keys,text width=35mm,minimum height=23mm] (c) at (49mm,-56mm) {\textbf{C}\\prefix\\may stop early};
\draw[arr] (opened)--(a); \draw[arr] (opened)--(b); \draw[arr] (opened)--(c);

\end{tikzpicture}
\caption{Every method can miss a global result if its cluster was not opened. B and C can introduce another loss if their local search stops before reaching that document.}
\end{figure}




\subsubsection{Method A}

Let:

\[
g_q
\]

be the number of global reference documents whose clusters were opened.

A scores every document in those clusters.

So all \(g_q\) of those reference documents are recovered locally.

Therefore:

\[
\boxed{
R_{A,q}
=
\frac{g_q}{K}.
}
\]

A can lose recall during cluster selection, but not during its local scan.



\subsubsection{Method B}

Suppose B recovers fraction:

\[
r_{B,q}
\]

of the reference documents that are already inside the opened clusters.

Then:

\[
\boxed{
R_{B,q}
=
\frac{g_q}{K}
r_{B,q}.
}
\]

For example, suppose:

\begin{itemize}\setlength{\itemsep}{1pt}
\item 8 of the 10 correct documents are inside the opened clusters;
\item B finds 6 of those 8.
\end{itemize}

Then:

\[
Recall
=
\frac{8}{10}
\times
\frac{6}{8}
=
60\%.
\]

If B performs a complete branch-and-bound search using valid score bounds, then:

\[
r_{B,q}=1.
\]

If we give B a finite node budget, it may stop early and reduce recall.

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- B recall:} Routing can lose documents before B even starts, and a limited Bitplane search can lose additional documents inside the opened clusters.}}\end{center}



\subsubsection{Method C}

Let:

\[
D_{q,\ell}
\]

be all documents exposed when Backward Walk stops at prefix depth \(\ell\).

Every document in that set has received the full score.

So:

\[
\boxed{
R_{C,q}
=
\frac{|G_q\cap D_{q,\ell}|}{K}.
}
\]

The important point is:

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{The number of documents inside a prefix does not tell us its recall.}}}\end{center}

A prefix can contain many documents and still miss the best result.



\Needspace{4\baselineskip}
\textbf{Small example}\par

Take:

\[
q=[0.1,\ 0.9].
\]

The ideal binary pattern is:

\texttt{11}.

Suppose the only two documents are:

\texttt{10}

and:

\texttt{01}.

Their scores are:

\[
S(10)=0.1-0.9=-0.8,
\]

\[
S(01)=-0.1+0.9=0.8.
\]

If C searches:

\texttt{1*}

it finds \texttt{10}.

But the better document is \texttt{01}, which lies outside that prefix.

So simply finding one document does not prove that we found the best document.



\Needspace{4\baselineskip}
\textbf{When is C exact inside the opened clusters?}\par

C can become exact in two ways.

The simple way is to keep relaxing until depth zero.

At depth zero, every document inside the opened clusters has been exposed, so C becomes equivalent to A locally.

The second way is to prove that the unseen documents cannot win.

At prefix depth \(\ell\), every unseen document must disagree with the query in at least one of the first \(\ell\) bits.

The cheapest such mismatch is:

\[
m_\ell
=
\min_{1\le i\le\ell}|q_i|.
\]

So the best possible score of any unseen document is:

\[
\boxed{
U_\ell
=
Q-2m_\ell.
}
\]

Let \(\tau\) be the worst score currently inside the top-\(K\).

If:

\[
\boxed{
\tau>U_\ell,
}
\]

then no unseen document inside the opened clusters can enter the result.

C can stop safely.

\Needspace{6\baselineskip}
\begin{center}\setlength{\fboxsep}{9pt}\fcolorbox{Ink!25}{Soft}{\parbox{.91\linewidth}{\textbf{TL;DR --- C recall:} Stopping after “enough documents” is only an approximation. C is exact locally only when it has either exposed every document or mathematically proved that the unseen documents cannot beat the current top-\(K\).}}\end{center}
