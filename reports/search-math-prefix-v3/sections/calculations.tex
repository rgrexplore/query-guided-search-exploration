\section{Preliminary calculations}
Before running the experiments, let's first understand what each method actually spends time and memory on.

The goal here is not to predict the exact latency from equations alone. A full document score, a bitmap operation and a binary search do not cost the same amount of CPU time, and their actual cost also depends on memory access and caching.

Instead, we want to answer three simpler questions:
\begin{enumerate}
\item \textbf{What work grows when the collection becomes larger?}
\item \textbf{Which parameters control that work?}
\item \textbf{What does Method B or C need to save in order to make its additional index work worthwhile?}
\end{enumerate}
We will later measure the actual latency, but these calculations give us a clearer idea of what to look for in the experiments.

Throughout this section:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $N$: total number of documents.
\item $C$: number of clusters.
\item $P$: number of clusters opened for one query.
\item $d$: number of binary dimensions.
\item $K$: number of requested results.
\item $n_c$: number of rows in cluster $c$.
\item $F_A,F_B,F_C$: number of documents fully scored by A, B and C respectively.
\end{itemize}
When clusters are approximately balanced,
\[
n\approx N/C
\]
and opening $P$ clusters exposes roughly
\[
Pn=PN/C
\]
documents. This is only an approximation. In the experiments we use the actual cluster sizes.

\subsection{Query-time work}
To make the three methods easier to compare, let's use the same small example throughout.

Suppose we have one cluster containing three documents:
\begin{center}
\begin{tabular}{@{}cl r@{}}\toprule
ID & Binary document & Full score\\\midrule
0 & \texttt{10100} & 0.1\\
1 & \texttt{11001} & 2.5\\
2 & \texttt{11000} & 1.9\\\bottomrule
\end{tabular}
\end{center}
and the query is
\[
q=[0.7,\ 0.5,\ -0.4,\ -0.6,\ 0.3].
\]
The ideal binary signs are \texttt{11001} and we want the best $K=2$ documents.

For this example:
\[
N=3,\qquad C=P=1,\qquad d=5.
\]
These three rows are only for explaining the algorithms. The experiments later use the full collections.

\subsubsection{Method A: scan the selected clusters}
Method A is the simplest.

Once routing has decided which clusters to open, every document inside those clusters receives the complete score.

\Needspace{4\baselineskip}
\textbf{Step 1: select the documents that must be searched}\par
For our example, we open the only cluster: \texttt{[ID 0, ID 1, ID 2]} so $F_A=3$.

In general,
\[
\boxed{F_A=\sum_{c\in O}n_c}
\]
where $O$ is the set of opened clusters.

If the clusters are roughly balanced,
\[
F_A\approx\frac{PN}{C}.
\]
This number is the main source of work for A.

\begin{figure}[htbp]\centering
\begin{tikzpicture}[node distance=4mm]
\node[scan,text width=16mm] (q) {Query};
\node[scan,text width=26mm,right=of q] (route) {Select $P$\\clusters};
\node[scan,text width=27mm,right=of route] (rows) {$F_A$ documents\\\texttt{10100}\\\texttt{11001}\\\texttt{11000}};
\node[scan,text width=30mm,right=of rows] (score) {Full score\\every document};
\node[scan,text width=16mm,right=of score] (top) {Top $K$};
\draw[arr](q)--(route);\draw[arr](route)--(rows);\draw[arr](rows)--(score);\draw[arr](score)--(top);
\end{tikzpicture}
\caption{Method A performs no additional filtering after routing. Every row in the opened clusters reaches the full scorer.}
\end{figure}

\Needspace{4\baselineskip}
\textbf{Step 2: prepare the score table}\par
The scorer groups four document signs together.

For $d=5$, the query becomes two groups: \texttt{[0.7, 0.5, -0.4, -0.6]} and \texttt{[0.3, 0, 0, 0]}.

Each four-bit group has $2^4=16$ possible sign patterns. So our example builds $2\times16=32$ table entries.

In general, let
\[
G=\left\lceil\frac d4\right\rceil.
\]
Building the table costs $O(d)$ for a fixed group width. One document score then reads $G$ entries.

\Needspace{4\baselineskip}
\textbf{Step 3: score every selected row}\par
Our three documents require $3\times2=6$ score-table lookups.

More generally, the scoring work is proportional to $F_AG$. Since $G$ is proportional to $d$,
\[
T_{\text{score},A}=O(F_Ad).
\]
For fixed $d$, this is simply linear in $F_A$.

\Needspace{4\baselineskip}
\textbf{Step 4: retain the best K results}\par
As each score is produced, we maintain a bounded top-$K$ heap.

For our example:
\[
\begin{aligned}
&\texttt{[ID 0: 0.1]}\\
&\quad\downarrow\\
&\texttt{[ID 1: 2.5, ID 0: 0.1]}\\
&\quad\downarrow\\
&\texttt{[ID 1: 2.5, ID 2: 1.9]}
\end{aligned}
\]
Heap maintenance is bounded by
\[
O(F_A\log(K+1)).
\]

\Needspace{4\baselineskip}
\textbf{Total cost for A}\par
Let:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $T_{\text{common}}$ contain routing, score-table preparation and other work shared by a particular configuration;
\item $a_A$ be the average measured time to fully process one document, including its score and top-$K$ update.
\end{itemize}
Then the useful cost model is
\[
\boxed{T_A\approx T_{\text{common}}+F_Aa_A.}
\]
For balanced clusters,
\[
\boxed{T_A\approx T_{\text{common}}+\frac{PN}{C}a_A.}
\]
The main question for A is therefore simple:

\textbf{How few documents can routing send to the scorer while still meeting the required recall?}

Increasing $C$ usually makes each cluster smaller, but it may require a larger $P$ to recover the same neighbors.

\subsubsection{Method B: Bitplanes}
Bitplanes try to reduce $F_A$.

Instead of immediately scoring every selected document, B first spends some time filtering documents using the query bits.

So B has two main costs:
\[
\boxed{\text{bitmap traversal}+\text{full scoring of the survivors}.}
\]
The method is useful only if the scoring it avoids is worth more than the bitmap work it adds.

\Needspace{4\baselineskip}
\textbf{Step 1: order the query bits}\par
B uses the same routing and score table as A. It additionally sorts the query coordinates by decreasing magnitude.

For
\[
q=[0.7,\ 0.5,\ -0.4,\ -0.6,\ 0.3],
\]
the order is
\[
\text{Bit 1 }(0.7)\to\text{Bit 4 }(0.6)\to\text{Bit 2 }(0.5)\to\text{Bit 3 }(0.4)\to\text{Bit 5 }(0.3).
\]
Sorting costs $O(d\log d)$. We also calculate
\[
Q=\sum_i|q_i|=2.5.
\]
\begin{figure}[htbp]\centering
\begin{tikzpicture}[node distance=10mm]
\node[scan,text width=40mm] (route) {Select $P$ clusters};
\node[branch,text width=62mm,right=of route] (order) {Order bits by $|q_i|$\\$1\to4\to2\to3\to5$};
\draw[arr](route)--(order);
\end{tikzpicture}
\caption{B keeps the same routing stage as A, then adds query-dependent filtering inside the opened clusters.}
\end{figure}

\Needspace{4\baselineskip}
\textbf{Step 2: split a candidate mask}\par
A candidate mask has one bit for every document position in the cluster.

If cluster $c$ contains $n_c$ documents, its mask contains
\[
\boxed{W_c=\left\lceil\frac{n_c}{64}\right\rceil}
\]
64-bit machine words.

Our three-document example has only one word. The initial mask is \texttt{111} meaning that all three rows are active.

\textbf{First split}\par
Bit 1 prefers \texttt{1}. All documents match: \texttt{111 AND 111 = 111}. Nothing is removed.

\textbf{Second split}\par
Bit 4 prefers \texttt{0}. Again all three documents match: \texttt{111 AND 111 = 111}. Nothing is removed.

Here the second \texttt{111} is the preferred zero-sign mask, obtained by complementing the stored bitplane \texttt{000}.

\textbf{Third split}\par
Bit 2 prefers \texttt{1}. Its bitplane is \texttt{011}. So: \texttt{111 AND 011 = 011}.

The preferred branch contains IDs 1 and 2. The alternative branch is \texttt{100} containing ID 0.

Because ID 0 disagrees with the query on bit 2, that branch has penalty
\[
p=|q_2|=0.5.
\]

\end{figure}

\Needspace{4\baselineskip}
\textbf{Step 3: understand what one split actually costs}\par
A common source of confusion is to think:

``A bitwise AND is one CPU operation, so this should be almost free.''

That is only true for one machine word.

If a cluster contains 6,400 documents,
\[
W=6400/64=100
\]
machine words. One split must therefore iterate across roughly 100 word positions.

More importantly, the physical bitmap width does \textbf{not} shrink when the logical candidate count shrinks.

A node may contain only 80 active documents while still occupying 100 words.

\begin{figure}[htbp]\centering
\begin{tikzpicture}
\node[anchor=west,font=\small] at (0,9mm) {Initial mask: 6,400 active candidates};

\node[anchor=west,font=\small] at (0,-12mm) {Later mask: 80 active candidates};

\end{tikzpicture}
\caption{Removing candidates does not shorten a dense bitmap. Later splits can still scan the full physical mask.}
\end{figure}
This is the main reason Bitplanes can become expensive.

\Needspace{4\baselineskip}
\textbf{Step 4: count split-mask work}\par
Let $J_c$ be the number of split nodes visited in cluster $c$. Each split scans $W_c$ words.

Therefore the exact split-word count is
\[
\boxed{V_{\text{split}}=\sum_{c\in O}J_cW_c.}
\]
This is better than immediately writing a balanced-cluster approximation because it also works for uneven clusters.

If clusters are approximately balanced and B performs an average of $S$ splits per opened cluster,
\[
V_{\text{split}}\approx PS\left\lceil\frac{N}{64C}\right\rceil.
\]

\Needspace{4\baselineskip}
\textbf{Step 5: score the leaf nodes}\par
Eventually, B stops splitting a candidate set and fully scores its remaining rows.

In our example, we choose leaf size 2. The preferred branch contains exactly two rows: \texttt{011} $\to$ IDs 1 and 2.

So B scores:
\begin{itemize}\setlength{\itemsep}{1pt}
\item ID 1 $\to$ 2.5
\item ID 2 $\to$ 1.9
\end{itemize}
and therefore $F_B=2$. A would have scored all three.

\textbf{Leaf masks still cost work}\par
Before extracting the surviving IDs, the implementation also scans the leaf bitmap.

Let $H_c$ be the number of leaf masks read in cluster $c$. Then
\[
\boxed{V_{\text{leaf}}=\sum_{c\in O}H_cW_c.}
\]
This is worth keeping separate from split-mask work because the experiments record the two counters separately.

\Needspace{4\baselineskip}
\textbf{Step 6: prune the waiting branch}\par
ID 0 is still waiting. Its accumulated mismatch penalty is $p=0.5$.

From the earlier score identity,
\[
S=Q-2p.
\]
The identity uses the total penalty of a fully known document. For a branch, the known penalty gives an upper bound.

So the best possible score anywhere inside that branch is
\[
2.5-2(0.5)=1.5.
\]
Our current top two are $2.5,\qquad1.9$. Because $1.5<1.9$, ID 0's branch cannot enter the top two. We skip it.

\begin{figure}[htbp]\centering
\begin{tikzpicture}[node distance=20mm]
\node[box,draw=gray,dashed,fill=gray!7,text width=45mm] (wait) {Waiting branch\\penalty = 0.5\\best possible = 1.5};
\node[branch,text width=40mm,right=of wait] (top) {Current top-2\\2.5\\1.9};
\draw[arr](wait)--node[above,font=\small] {$1.5<1.9$}(top);
\node[below=5mm of wait,font=\small\bfseries,text=gray] {PRUNE};
\end{tikzpicture}
\caption{Once a branch's best possible score is below the current top-$K$ threshold, the entire branch can be skipped.}
\end{figure}

\Needspace{4\baselineskip}
\textbf{Total cost for B}\par
B therefore pays for:
\begin{enumerate}\setlength{\itemsep}{1pt}
\item sorting the query bits;
\item split-mask scans;
\item leaf-mask scans;
\item priority-queue and branch management;
\item full scores for $F_B$ surviving rows.
\end{enumerate}
Let:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $b_s$: average time for one split-word visit;
\item $b_l$: average time for one leaf-word visit;
\item $T_{\text{queue}}$: queue, allocation and branch bookkeeping, including initial mask creation;
\item $T_{\text{order}}$: sorting and query-weight preparation.
\end{itemize}
Then:
\[
\boxed{T_B\approx T_{\text{common}}+T_{\text{order}}
+b_sV_{\text{split}}+b_lV_{\text{leaf}}+F_Ba_B+T_{\text{queue}}.}
\]
For approximately balanced clusters,
\[
\begin{aligned}
T_B\approx{}&T_{\text{common}}+T_{\text{order}}
+PS\left\lceil\frac{N}{64C}\right\rceil b_s\\
&+PH\left\lceil\frac{N}{64C}\right\rceil b_l
+F_Ba_B+T_{\text{queue}},
\end{aligned}
\]
where $H$ is the average number of leaf masks per opened cluster.

This is the main tradeoff:
\[
\boxed{\text{time saved from avoided scores}>\text{bitmap + branch overhead}.}
\]
A smaller leaf size may reduce $F_B$, but usually increases $V_{\text{split}}$.

That is why ``B scores fewer documents'' by itself does not prove that B is faster.

\subsubsection{Method C: Backward Walk}
Backward Walk approaches the problem from the opposite direction.

A starts with every row in the opened clusters. B also starts broad, then narrows the candidate set. C starts with a \textbf{very specific binary prefix} and progressively makes it broader.

So its two main costs are:
\[
\boxed{\text{prefix navigation}+\text{full scoring of the exposed rows}.}
\]

\Needspace{4\baselineskip}
\textbf{Step 1: store rows in prefix order}\par
For the same three documents, suppose the stored key width is five bits.

We sort them:
\begin{center}
\begin{tabular}{@{}rlr@{}}\toprule
Position & Key & ID\\\midrule
0 & \texttt{10100} & 0\\
1 & \texttt{11000} & 2\\
2 & \texttt{11001} & 1\\\bottomrule
\end{tabular}
\end{center}
The query's ideal key is \texttt{11001}.

\Needspace{4\baselineskip}
\textbf{Step 2: look up the deepest prefix}\par
Suppose we start at depth $x=5$. We search for \texttt{11001}.

Because the keys are sorted, two binary searches find the start and end of its range. The result is $[2,3)$ containing only ID 1.

We score ID 1: $2.5$. But we need two results, so we continue.

\Needspace{4\baselineskip}
\textbf{Step 3: remove one prefix constraint}\par
We move from \texttt{11001} to \texttt{1100*}.

Its range is $[1,3)$ containing IDs 2 and 1. ID 1 was already processed.

Therefore we only score the \textbf{new part} of the range: $[1,2)\to$ ID 2. ID 2 scores $1.9$. Now we have two candidates.

\end{tikzpicture}
\caption{Relaxing a prefix enlarges the previous range. Already-scored rows stay inside the new range, so C only scores the newly exposed rows.}
\end{figure}

\Needspace{4\baselineskip}
\textbf{Step 4: count how many prefix levels are visited}\par
Let:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $x$: starting prefix depth;
\item $\ell$: final prefix depth.
\end{itemize}
Then $L=x-\ell+1$ prefix levels are visited.

Depth zero represents the whole cluster and needs no binary search. Let $L_+$ be the number of visited depths greater than zero.

For each positive depth and each selected cluster, we perform two boundary searches. So the number of binary-search calls is:
\[
\boxed{2PL_+.}
\]
If cluster $c$ contains $n_c$ rows, one binary search takes $O(\log(n_c+1))$ key comparisons.

Therefore the lookup work is approximately
\[
\boxed{2L_+\sum_{c\in O}\log_2(n_c+1).}
\]
For balanced clusters:
\[
\boxed{2PL_+\log_2\left(\frac NC+1\right).}
\]

\Needspace{4\baselineskip}
\textbf{Step 5: count the distinct rows scored}\par
Let $F_C$ be the total number of distinct rows exposed before Backward Walk stops.

Because every wider prefix contains the previous prefix, each document only needs to be scored once. So the full-scoring term is simply $F_Ca_C$.

The critical question for C is therefore not really the binary search. It is:

\textbf{How large does the prefix range become before we can stop?}

\Needspace{4\baselineskip}
\textbf{Step 6: simple intuition for prefix size}\par
To understand this, suppose temporarily that the bits are:
\begin{itemize}\setlength{\itemsep}{1pt}
\item independent;
\item balanced;
\item equally likely to be \texttt{0} or \texttt{1}.
\end{itemize}
Then an $\ell$-bit prefix has probability $2^{-\ell}$.

In a cluster containing $n$ documents, the expected range size is $n/2^\ell$. Across $P$ balanced clusters:
\[
\boxed{E[F_\ell]\approx\frac{PN}{C2^\ell}.}
\]
For one global collection containing one million rows:
\begin{center}
\begin{tabular}{@{}rr@{}}\toprule
Prefix depth & Expected matching rows\\\midrule
16 & about 15\\
15 & about 31\\
14 & about 61\\
13 & about 122\\
12 & about 244\\\bottomrule
\end{tabular}
\end{center}
So dropping one bit approximately doubles the candidate set.

Real embedding bits can be correlated, and clustering can make their distribution even less uniform.

\Needspace{4\baselineskip}
\textbf{Step 7: approximate stopping versus exact stopping}\par
There are two different ways Backward Walk can stop.

\textbf{Approximate stopping}\par
Stop after at least $M$ candidates have been found.

This is cheap and simple, but: finding enough candidates does not prove that the best unseen document is worse. So recall has to be measured.

\textbf{Exact local stopping}\par
At prefix depth $\ell>0$, every unseen row must disagree with the query in at least one of the first $\ell$ bits.

Therefore its mismatch penalty is at least
\[
m_\ell=\min_{1\le i\le\ell}|q_i|.
\]
Its best possible score is therefore:
\[
\boxed{U_\ell=Q-2m_\ell.}
\]
Let $\tau$ be the worst score currently retained in the full top-$K$ heap. If:
\[
\boxed{\tau>U_\ell,}
\]
with the implementation's tie and rounding rules handled correctly, no unseen row in the opened clusters can improve the answer. The search can stop safely.

This distinction should be stated clearly because a candidate target and a mathematical score bound provide very different guarantees.

\Needspace{4\baselineskip}
\textbf{Total cost for C}\par
Let:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $T_{\text{key}}$: build the query key and any bound-related query data;
\item $t_b$: average time per binary-search key comparison;
\item $T_{\text{ranges}}$: range updates and new-slice bookkeeping.
\end{itemize}
The optional bound checks are included in $T_{\text{ranges}}$.

Then:
\[
\boxed{\begin{aligned}
T_C\approx{}&T_{\text{common}}+T_{\text{key}}
+2L_+t_b\sum_{c\in O}\log_2(n_c+1)\\
&+F_Ca_C+T_{\text{ranges}}.
\end{aligned}}
\]
For balanced clusters:
\[
\boxed{\begin{aligned}
T_C\approx{}&T_{\text{common}}+T_{\text{key}}
+2PL_+\log_2\left(\frac NC+1\right)t_b\\
&+F_Ca_C+T_{\text{ranges}}.
\end{aligned}}
\]
The binary-search part grows slowly with cluster size. The main question is $F_C$.

If C stops at a deep prefix, $F_C\ll F_A$, and it may save substantial scoring work.

If C has to widen all the way to depth zero, $F_C=F_A$, so it performs the same full scoring as A \textbf{plus} its prefix-search overhead.

\subsubsection{Query-time comparison}
At this point the three methods are easier to compare:
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lYY@{}}\toprule
Method & What it mainly pays for & What it tries to reduce\\\midrule
A & Full scores for all opened rows & Nothing after routing\\
B & Bitmap traversal + surviving full scores & Number of full scores\\
C & Prefix navigation + exposed full scores & Number of full scores\\\bottomrule
\end{tabularx}
\end{center}
A useful compact formula table is:
\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lY@{}}\toprule
Method & Query-time model\\\midrule
A & $T_{\text{common}}+F_Aa_A$\\
B & $T_{\text{common}}+T_{\text{order}}+b_sV_{\text{split}}+b_lV_{\text{leaf}}+F_Ba_B+T_{\text{queue}}$\\
C & $T_{\text{common}}+T_{\text{key}}+T_{\text{lookup}}+F_Ca_C+T_{\text{ranges}}$\\\bottomrule
\end{tabularx}
\end{center}
where
\[
T_{\text{lookup}}=2L_+t_b\sum_{c\in O}\log_2(n_c+1).
\]
The main conditions are therefore:

\textbf{Method B}
\[
\boxed{\text{scoring avoided}>\text{bitmap and branch work added}.}
\]
\textbf{Method C}
\[
\boxed{\text{scoring avoided}>\text{prefix navigation and range work added}.}
\]
The experiment later checks whether either condition actually occurs.

\subsection{Memory complexity}
There are two different kinds of memory:

\textbf{stored index memory}, which remains allocated between queries, and
\textbf{temporary query memory}, which only exists while a query is running.

\subsubsection{Method A}
\textbf{Stored index}\par
Every document stores:
\begin{itemize}\setlength{\itemsep}{1pt}
\item its packed binary code;
\item its document ID.
\end{itemize}
With 64-bit words, one code occupies
\[
8\left\lceil\frac d{64}\right\rceil
\]
bytes. An ID occupies 8 bytes. So:
\[
\boxed{M_{A,\text{rows}}=N\left(8\left\lceil\frac d{64}\right\rceil+8\right).}
\]
Routing structures are additional. For float32 centroids with routing dimension $d_R$:
\[
M_{\text{routing}}\approx4Cd_R+8C,
\]
plus cluster offsets and implementation overhead.

\textbf{Query memory}\par
A needs:
\begin{itemize}\setlength{\itemsep}{1pt}
\item floating-point query;
\item score table;
\item top-$K$ results;
\item small routing/search state.
\end{itemize}
For the current field layout:
\[
Q_0=4d+128\left\lceil\frac d4\right\rceil+16K
\]
bytes for the named query, table and result fields.

\textbf{Small example}\par
With three five-bit documents:
\begin{itemize}\setlength{\itemsep}{1pt}
\item codes: $3\times8=24$ bytes;
\item IDs: $3\times8=24$ bytes.
\end{itemize}
So the named document fields use 48 bytes.

The exact number is not important; it simply gives us a baseline for comparing B and C.

\subsubsection{Method B}
B keeps everything A stores. It adds two things:
\begin{enumerate}\setlength{\itemsep}{1pt}
\item stored bitplanes;
\item temporary branch masks.
\end{enumerate}

\textbf{Stored bitplanes}\par
For coordinate $i$, cluster $c$ needs $W_c$ words. There are $d$ coordinates. Therefore:
\[
\boxed{M_{\text{planes}}=8d\sum_{c=1}^{C}W_c.}
\]
with $W_c=\left\lceil n_c/64\right\rceil$. Notice the per-cluster padding.

\textbf{Temporary masks}\par
One live mask for cluster $c$ uses $8W_c$ bytes.

If several branches are waiting, several full-width masks may be alive at once.

If $A_c(t)$ masks from cluster $c$ are live at time $t$,
\[
\boxed{Q_{\text{masks}}=8\max_t\sum_c A_c(t)W_c.}
\]
The query also keeps:
\begin{itemize}\setlength{\itemsep}{1pt}
\item sorted bit positions;
\item priority-queue records;
\item node metadata.
\end{itemize}

\subsubsection{Method C}
C also keeps A's packed documents and IDs.

In the current sorted-key implementation it adds one 32-bit prefix key per row. So:
\[
\boxed{M_{\text{prefix}}=4N}
\]
bytes. Documents are sorted once by this key inside each cluster.

We do \textbf{not} store a separate posting list for every prefix depth. The same sorted rows support \texttt{11001}, \texttt{1100*}, \texttt{110**} and so on.

This is important because otherwise prefix relaxation could duplicate a large amount of storage.

\textbf{Query memory}\par
For every opened cluster, C only needs to remember the previously visited range: $[\text{left},\text{right})$.

In the current 64-bit implementation, a selected-cluster record contains approximately:
\begin{itemize}\setlength{\itemsep}{1pt}
\item 8-byte cluster pointer;
\item 8-byte left boundary;
\item 8-byte right boundary.
\end{itemize}
So about $24P$ bytes. The current query key uses another four bytes.

Optional exact-stop data adds small $O(x)$ query state. The prefix minima and query sum use $8x+8$ named bytes when the optional bound is enabled at a positive starting depth; they are absent otherwise.

The field formulas describe the logical data. Actual process RAM can be larger because of:

\begin{enumerate}\setlength{\itemsep}{1pt}

\end{enumerate}

\subsection{Recall}
The complexity formulas tell us how much work a method performs. They do \textbf{not} tell us whether the correct documents survive. So recall is measured directly from document IDs.

For every query $q$, let:
\begin{itemize}\setlength{\itemsep}{1pt}
\item $G_q$: exact reference top-$K$ IDs;
\item $O_{a,q}$: IDs returned by method $a$.
\end{itemize}
Then:
\[
\boxed{R_a=\frac{\sum_q|G_q\cap O_{a,q}|}{n_qK}.}
\]
Here $n_q$ is the number of queries.

For example: reference \texttt{[1,2]}, returned \texttt{[1,0]} gives $1/2=50\%$. Returning \texttt{[1,2]} gives 100\%.

\begin{tikzpicture}[node distance=8mm]

\node[box,text width=105mm,below=of global] (routed) {Reference IDs whose clusters were opened\\$g_q$};
\draw[arr](global)--node[right,font=\small] {routing}(routed);

\caption{Recall can be lost during routing, and B or C may introduce an additional local-search loss if they stop early.}
\end{figure}

\subsubsection{Method A}
Let $g_q$ be the number of global reference IDs whose clusters are opened.

A fully scores every opened row. Therefore every one of those $g_q$ reference documents is recovered locally. So:
\[
\boxed{R_{A,q}=\frac{g_q}{K}.}
\]
A can lose recall through routing, but not through its local scan.

\subsubsection{Method B}
Among the $g_q$ reference IDs that reached the opened clusters, suppose B recovers fraction $r_{B,q}$. Then:
\[
\boxed{R_{B,q}=\frac{g_q}{K}r_{B,q}.}
\]
If $g_q=0$, recall is zero.

Example:
\begin{itemize}\setlength{\itemsep}{1pt}
\item 8 of 10 reference IDs reach the opened clusters;
\item B returns 6 of those 8.
\end{itemize}
Then:
\[
(8/10)(6/8)=60\%.
\]
If B runs its complete branch-and-bound traversal using safe score bounds and correct tie handling, $r_{B,q}=1$.

A finite node budget can make $r_{B,q}<1$.

\subsubsection{Method C}
Let $D_{q,\ell}$ be the set of rows exposed when Backward Walk stops at prefix depth $\ell$.

Every row in $D_{q,\ell}$ has received the complete score. Therefore:
\[
\boxed{R_{C,q}=\frac{|G_q\cap D_{q,\ell}|}{K}.}
\]
The important point is: the number of candidates in the prefix does not tell us its recall.

A prefix may contain many documents but still miss the best document.

\textbf{Small counterexample}\par
Let $q=[0.1,\ 0.9]$. The ideal signs are \texttt{11}.

Suppose the only documents are \texttt{10} and \texttt{01}. Their scores are:
\[
\begin{aligned}
\texttt{10}&\to0.1-0.9=-0.8\\
\texttt{01}&\to-0.1+0.9=0.8.
\end{aligned}
\]
If C relaxes the query to \texttt{1*} it finds \texttt{10}. But \texttt{01}, which lies outside that prefix, is actually better.

So: \textbf{finding one candidate is not a proof that the best candidate has been found.}

This is why candidate-target stopping is approximate.

\Needspace{4\baselineskip}
\textbf{When is C exact inside the opened clusters?}\par
There are two ways.

\textbf{1. Reach depth zero}\par
At depth zero, every row in every opened cluster has been exposed. Therefore C becomes equivalent to A inside those clusters.

\textbf{2. Prove that unseen rows cannot win}\par
At depth $\ell>0$, every unseen row differs from the query in at least one of the first $\ell$ signs. The cheapest possible such mismatch is:
\[
m_\ell=\min_{1\le i\le\ell}|q_i|.
\]
So every unseen row has score at most:
\[
U_\ell=Q-2m_\ell.
\]
If the current worst top-$K$ score is $\tau$ and $\tau>U_\ell$, with tie and floating-point rounding handled safely, C can stop exactly within the opened clusters.

This is a much stronger condition than simply finding $K$ candidates.

\Needspace{10\baselineskip}
\begin{center}
\fcolorbox{Ink!35}{Soft}{\parbox{0.93\linewidth}{
\textbf{Rough intuition only.} Suppose $p_i$ is the probability that an opened reference document agrees with the query at prefix coordinate $i$. If these agreement events were independent, the fraction agreeing with all first $\ell$ positions would be approximately
\[
\prod_{i=1}^{\ell}p_i.
\]
This is not used as the reported recall. Real coordinates can be dependent, so the experiment measures recall directly from returned IDs.
}}
\end{center}
