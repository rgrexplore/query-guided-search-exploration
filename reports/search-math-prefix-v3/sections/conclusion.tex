\section{Limitations and next steps}
\Needspace{4\baselineskip}
\textbf{Environment might be different.}\par
In this experiment, all three methods are tested using the same CPU implementation and the same document scoring code. This gives us a fair comparison inside this report, but a production system may behave differently. For example, Exa may use a more optimized scorer, different SIMD kernels, or a different memory layout. If document scoring becomes much cheaper, then avoiding a scoring operation also becomes less valuable. One useful extension would be to test the same methods in a more production-like environment, or against an implementation closer to the system described by Exa.

\Needspace{5\baselineskip}
\textbf{Bitplanes are effective for small $K$, but the benefit becomes less predictable as $K$ grows.}\par
In the experiments, Bitplanes perform very well when we only need a small number of results. The reason is that many branches can be ignored once we already have a strong top result. However, when $K$ becomes larger, more branches may still contain one of the required documents, so B has to keep exploring and the extra bitmap work can start to dominate. One possible direction for future work is to predict, from the query and the requested $K$, whether Bitplanes are likely to be useful before running them.

\Needspace{4\baselineskip}
\textbf{Backward Walk still needs further investigation.}\par
The current version works best when a fairly specific query prefix already contains useful documents. If that prefix is too restrictive, the method has to keep broadening it, and eventually it may expose a large part of the opened clusters. A useful next step would be to study better ways of choosing the starting prefix, the order of the prefix bits, or when to stop broadening.

\Needspace{4\baselineskip}
\textbf{Real retrieval quality still needs to be investigated.}\par
The recall measured in this report is based on the exact ranking of the binary index being tested. For example, 99\% recall with a 32-bit representation means recovering 99\% of the exact 32-bit binary results. It does not necessarily mean that those results match the original full embedding or the documents that are most relevant to a user. A more complete evaluation should also compare against the full embedding and, where possible, human relevance labels.

\Needspace{4\baselineskip}
\textbf{Other operations, such as index updates, also matter in production.}\par
The experiments here focus on query-time search, but a real search system also needs to insert, delete and update documents while continuing to serve queries. This is especially interesting for Backward Walk, because its prefix-based index may be simpler to update than a graph-based structure, but that has not been measured yet. Future work should therefore look at both query latency and index-maintenance cost.
