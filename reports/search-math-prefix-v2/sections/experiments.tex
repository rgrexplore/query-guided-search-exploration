\section{Experiments}
\subsection{Setup}
To see where each method helps, I started with 256-bit codes from two collections. I then added shorter and longer codes from the same cached embeddings. Within one setup, A, B and C receive exactly the same document codes, query vectors and reference IDs. I change the index and search settings, then compare the time needed to reach the same recall target.

\begin{center}\small
\begin{tabular}{@{}llrrl@{}}\toprule
Collection & Embedding model & Documents & Queries & Bits\\\midrule
MS MARCO & Nomic v1.5 & 1,000,000 & 1,000 & 64, 256, 768\\
Quora (BEIR) & Qwen3 0.6B & 522,931 & 1,000 & 32, 256, 1024\\\bottomrule
\end{tabular}
\end{center}
I reused the cached Nomic document embeddings and selected 1,000 queries from MS MARCO's official \texttt{dev.small} file~\cite{msmarco,nomic}. For Quora, I encoded the full BEIR corpus and selected 1,000 official test queries~\cite{beir,qwen}. Both random selections were fixed before search. Corpus duplicates remain; none of the selected Quora queries has identical text or ID in its corpus.

Each model produces a full vector once. I take supported prefixes, normalize them, and store their signs. Each length has its own reference: score every document and keep the best 100, resolving ties by document ID. The first one or ten IDs give the smaller result sets. Recall here measures recovery of these binary-score references; human relevance labels are a separate measure.

The machine is an Apple M5 Max with 128 GiB of memory. I use one native search query at a time and one Faiss search thread, with the same 32 GB process limit for all methods. Reported query time starts with a cached query vector and ends with the returned IDs. It includes selecting clusters and searching their documents. Embedding generation and text reranking are outside this timer. Encoding and reference preparation finish before timed searches begin.

\subsection{Parameters}
For each cluster layout, I first count how many probes are needed to include the required fraction of reference IDs. A scores every document in those clusters, so it can recover all of those opened reference IDs. I give B and C the same probe choices; their local search can still miss a result, so they may need to open more clusters to reach the target.

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}lY@{}}\toprule
Parameter & First sweep\\\midrule
Number of clusters & 1, 64, 1024, 4096\\
Results returned & 1, 10, 100\\
Average recall targets & 50\%, 80\%, 90\%, 95\%, 99\%\\
Opened clusters & Probe counts derived for those targets, plus every cluster\\
B: leaf size & 128 or 2048 documents\\
B: visited-set budget & 512 or 8192; both split nodes and leaves count\\
B: random exploration & 0; visit the lowest-penalty waiting set first\\
C: starting prefix & 16 bits\\
C: candidate target & 1,000; 10,000; 100,000; half the collection; or 0\\\bottomrule
\end{tabularx}
\end{center}
For C, target zero continues to depth zero and scores every opened document. A positive target stops after a complete depth has produced enough candidates. This can exceed the requested count when the next prefix contains many documents.

The two 256-bit grids each contain 570 settings. The wider Qwen grid keeps result counts 1 and 100; full-width Nomic focuses on 100 results at 95\% and 99\% recall. Across the first sweeps and follow-ups, 3,679 of 4,024 scheduled A/B/C settings qualify, plus all 72 probability settings. Time limits leave three grids partial. The saved study lists their completed and missing settings; only complete measurements enter the comparisons.

For shorter codes, I add leaves of 8 and 32 rows, probes aimed at 99.5\% routing coverage, and C starting depths 0, 1, 4, 16 and 32. B also tries visiting the deeper set first when penalties tie, instead of creation order. Both branches and the score bound stay unchanged.

I build clusters from either normalized float vectors or document signs scaled by $1/\sqrt d$. The second option trains on the representation used by the binary scorer. All methods receive both options with unchanged codes, queries and references. The short-code follow-ups include 16, 64, 256, 1024 and 4096 clusters.

C's exact-stop option uses target zero with starting depths 1, 4 and 32, alongside a depth-zero scan. A one-cluster Qwen32 run checks exact search over the whole collection. For B, a separate experiment holds the layout and leaf size fixed while comparing probabilities 0, 0.1 and 0.2, three seeds and two budgets. Probability changes which waiting branch we visit next; both alternatives are still kept.

Every completed setting uses all 1,000 queries, including settings that miss the recall target. I select each method's fastest qualifying settings and repeat those choices in three fresh processes with varied run order. Small batches and saved checkpoints limit the time lost to slow settings.

If B scores 512 whole clusters without splitting, its direct alternative is A with 512 probes. I add these missing A probe counts wherever B or C appears faster, and give C its depth-zero setting at A's selected layouts. Each method can therefore use the simpler scan when branching or widening adds no benefit.

\subsection{Code and reproduction}
The C++ scorer is shared by all three methods. A and B are in \path{cpp/index.cpp}; C is in \path{cpp/prefix_index_v2.cpp}. The Python worker in \path{experiments/prefix_batch_worker_v2.py} times routing and search, records the work counts, and compares returned IDs with the exact references.

After preparing the arrays using \path{experiments/prepare_prefix_pools_v2.py}, we can run one complete setup with this Python flow:
\begin{lstlisting}
import json
from pathlib import Path
from experiments import prefix_study_v2 as study
path = Path("configs/prefix-study-v2/qwen-quora-d256.json")
config = json.loads(path.read_text())
output = Path("results/my-quora-run")
study.prepare(config, output)  # Build clusters and the schedule.
study.run(output)             # Measure the declared settings.
study.summarize(output)       # Select by recall and time.
study.repeat(output)          # Repeat those choices three times.
\end{lstlisting}
The configurations are in \path{configs/prefix-study-v2/}; input hashes, per-query records, power settings and repeated times are in \path{results/prefix-study-2026-09-13/}. Its README links every final table and graph to the source measurements. \path{docs/expanded-pool-preparation.md} gives the data and encoding commands.

The root README maps the paper to its code. In particular, \path{experiments/prefix_comparison_v2.py} combines only runs with matching inputs; \path{experiments/prefix_exact_prediction_v2.py} checks prefix stopping counts; and \path{experiments/prefix_representation_v2.py} measures agreement with full float vectors.
