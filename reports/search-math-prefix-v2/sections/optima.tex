\section{When can B or C win?}
From the previous section, we already have an approximate time model for each method. We can now ask: under what conditions can Bitplanes or Backward Walk actually be faster than a full scan?

The methods still need to meet the same recall requirement and fit within the same available memory. Let $\rho$ be the required average recall and $B_{\max}$ the RAM budget in bytes. The budget is a parameter, not an intrinsic 32 GB limit: we can use 64 GB, 128 GB, or another allowance. Section 4 reports the limit and memory use of the runs actually performed.

The math will not directly give every final parameter. How many branches we visit, or how many reference documents lie behind a prefix, depends on the embeddings and queries. What we can derive is a \emph{break-even condition}: the point where time saved from scoring fewer documents exceeds the additional index work.

For the first comparisons, assume equal-sized clusters with $n=N/C$ rows each. We also use one approximate time $a$ to score a document and update the results. The actual row-access costs can differ, even with a shared scoring function, so we return to separate values $a_A,a_B,a_C$ when that matters.

\subsection{Find the best scan first}
A gives us the baseline that B and C need to beat. For a fixed cluster count $C$, fewer probes mean fewer opened documents, but possibly lower recall. We first find the smallest probe count that reaches the target:
\[
 \boxed{P_A(C,\rho)=\min\{P:\overline R_A(C,P)\ge\rho\}.}
\]
$\overline R_A$ is average recall over the fixed queries. For example, if a reference result is assigned to the fifth cluster in a query's routing order, we recover it only when $P\ge5$.

We can count those ranks before timing the search. Let $n_q$ be the number of queries, $K$ the requested results, and $s_{qi}^{(C)}$ the cluster rank of reference result $i$ for query $q$. Then
\[
 \overline R_A(C,P)=\frac{1}{n_qK}
 \sum_{q=1}^{n_q}\sum_{i=1}^{K}\mathbf 1[s_{qi}^{(C)}\le P].
\]
The indicator counts a reference ID when its cluster is open. If a cutoff splits tied centroid scores, I increase it until no query has a tie across that boundary. Every method receives the same available probe choices for that layout.

\textbf{How many clusters?}
Suppose routing costs $\alpha C$, where $\alpha$ is time per centroid, and processing a selected row costs $\beta$. Holding $P$ and the remaining setup time $T_{\rm fixed}$ constant gives
\[
 T_A(C)\approx T_{\rm fixed}+\alpha C+\beta\frac{NP}{C}.
\]
Differentiating and setting the result to zero,
\[
 \frac{dT_A}{dC}=\alpha-\frac{\beta NP}{C^2}=0,
 \qquad \boxed{C^*=\sqrt{\frac{\beta NP}{\alpha}}.}
\]
Too few clusters leave a large scan inside each one. Too many make routing more expensive. The derivative describes that balance only while $P$ is fixed. At fixed recall, $P_A(C,\rho)$ can change with $C$, and both quantities are integers. We therefore compare the actual cluster layouts and their qualifying probe counts rather than treating $C^*$ as the final answer.

We also compare the router choices available to every method, such as clusters trained from float vectors or binary document signs. The baseline we want is A's fastest qualifying tested setting, not one convenient cluster count that happens to make B or C look good.

\subsection{When do Bitplanes help?}
First let A and B open the same $P$ clusters. A fully scores $Pn$ rows. B performs an average of $S$ splits per cluster and fully scores a fraction $f_B$ of those rows. Each mask has $W=\ceil{n/64}$ words, and one split-word visit takes average time $b$.

Removing the common time $T_0$ from both methods gives
\[
 T_A-T_0\approx Pna,
 \qquad
 T_B-T_0\approx PSWb+f_BPna+T_{\mathrm{other},B}.
\]
$T_{\mathrm{other},B}$ includes query ordering, initial masks, queues and final-mask reads. B wins locally when
\[
 PSWb+f_BPna+T_{\mathrm{other},B}<Pna.
\]
Move its scoring term to the other side, then divide by the $Pn$ opened rows:
\[
 (1-f_B)Pna>PSWb+T_{\mathrm{other},B},
\]
\[
 \boxed{(1-f_B)a>\frac{SW}{n}b+
                  \frac{T_{\mathrm{other},B}}{Pn}.}
\]
The left side is scoring time saved per opened row. The right side is additional bitmap and branch work per opened row. If $n$ is large enough that word padding is negligible, $W/n\approx1/64$, giving the simpler form
\[
 (1-f_B)a>\frac{Sb}{64}+\frac{T_{\mathrm{other},B}}{Pn}.
\]
Equivalently, the surviving fraction must satisfy
\[
 \boxed{f_B<1-\frac{SWb}{na}-\frac{T_{\mathrm{other},B}}{Pna}.}
\]
If the right side is 0.6, for example, B must score less than 60\% of the opened documents to pay for its extra work. If it is zero or negative, even avoiding every full score would not pay for the work assumed in this calculation.

\textbf{How many splits?}
For a first estimate, suppose each split halves one followed set in each cluster. After $j$ splits, its remaining fraction is $2^{-j}$. Hold other branch costs constant for this calculation:
\[
 T_B(j)-T_0\approx P\left(jWb+n2^{-j}a\right)+T_{\mathrm{other},B}.
\]
The derivative is
\[
 \frac{dT_B}{dj}=P\left(Wb-na\ln(2)2^{-j}\right).
\]
Setting it to zero gives
\[
 \boxed{j^*=\log_2\!\left(\frac{na\ln(2)}{Wb}\right)
       \approx\log_2\!\left(\frac{64a\ln(2)}{b}\right).}
\]
The approximation on the right again ignores word padding. We would test nearby integer depths within $0\le j\le d$; a negative answer suggests no splitting under this model. This estimate describes one halving path, not a full branching search. Real splits may remove no rows, and exploring alternatives adds work, so it cannot supply a recall guarantee or directly choose the node budget.

The cancellation of $n$ explains why smaller clusters are not automatically better for B. Both the scan and a dense bitmap pass grow roughly linearly with cluster size. Smaller clusters can still change the branch counts, routing recall and cache behavior, and padding matters for very small clusters. Those effects appear in the measured $S$, $f_B$ and time per operation.

With actual cluster sizes and different row-access costs, the local condition is
\[
 \boxed{F_Aa_A-F_Ba_B>
       b\sum_{c\in\mathcal O}J_cW_c+T_{\mathrm{other},B}.}
\]
Here $\mathcal O$ is the common opened set, $J_c$ its split counts and $W_c$ its mask widths. This is what we inspect in the experiment: how many scores were avoided, and how much mask and branch work was needed to avoid them.

\subsection{When does Backward Walk help?}
\label{sec:prefix-optima}
Again, start with the same opened clusters. Let $F_C=f_CPn$ be the distinct rows C scores, where $f_C$ is their fraction of the opened set. Its additional costs are building the query key, finding prefix ranges and updating the newly exposed slices:
\[
 T_C-T_0\approx T_{\mathrm{key}}+
 2PL_+\log_2(n+1)t_b+f_CPna+T_{\mathrm{ranges}}.
\]
$L_+$ counts visited nonzero depths and $t_b$ is time per binary-search comparison. Depth zero needs no boundary search. Requiring $T_C<T_A$, then moving the scoring term, gives
\[
 (1-f_C)Pna>T_{\mathrm{key}}+
 2PL_+\log_2(n+1)t_b+T_{\mathrm{ranges}}.
\]
Divide by $P$ to see the average cost per opened cluster:
\[
 \boxed{(1-f_C)na>2L_+\log_2(n+1)t_b+
       \frac{T_{\mathrm{key}}+T_{\mathrm{ranges}}}{P}.}
\]
The left side is the scan time avoided; the right side is the prefix work added. Unlike a dense bitmap pass, each binary search grows logarithmically with $n$. Its cost relative to a full scan contains $\log(n+1)/n$, which falls as the cluster grows. That helps only if C can still stop with a small $f_C$. A larger cluster may instead force it to score many more documents.

For unequal cluster sizes or different scoring costs, we retain the full condition:
\[
 \boxed{F_Aa_A-F_Ca_C>T_{\mathrm{key}}+
 2L_+t_b\sum_{c\in\mathcal O}\log_2(n_c+1)+T_{\mathrm{ranges}}.}
\]
Each wider range contains the previous one, so only newly exposed rows contribute to $F_C$. If the walk reaches the root, it scores the whole opened set and loses that saving.

\textbf{Where should the walk start?}
Let $x$ be starting depth, $\ell$ ending depth and $M>0$ the candidate target. Under independent, balanced signs within the opened clusters, a \emph{fixed} depth $\ell$ would expose about $Pn/2^\ell$ rows. Matching that count to $M$ gives
\[
 \frac{Pn}{2^\ell}\approx M
 \quad\Longrightarrow\quad
 \boxed{\ell\approx\log_2\!\left(\frac{Pn}{M}\right).}
\]
For one million opened rows and about 100 candidates, this is $\log_2(10{,}000)\approx13.3$. Depths around 13 or 14 are therefore worth inspecting under that model; we could begin deeper and widen toward them. The stored key limits the available depths: $0\le x\le h\le\min(d,32)$ in this implementation.

This estimates a count, not whether those rows contain the best results. Correlated signs and clustering can make the count inaccurate too. We measure actual prefix sizes and reference membership rather than turning this estimate into a recall prediction.

\textbf{When can the walk stop exactly?}
After scoring a whole prefix range, we can sometimes prove that no unseen row can enter the results. Let $Q=\sum_{i=1}^{d}|q_i|$ be the ideal binary score and $\tau$ the worst of the $K$ scores currently kept. At positive depth $\ell$, an unseen row must disagree with at least one retained sign, so its score is at most
\[
 u_\ell=Q-2\min_{1\le i\le\ell}|q_i|,
 \qquad \boxed{\text{stop if }\tau>u_\ell.}
\]
The minimum appears because the best unseen row would choose the cheapest sign to get wrong. In our three-document example, prefix \texttt{1100*} contains scores 2.5 and 1.9. Its four weights are 0.7, 0.5, 0.4 and 0.6. An unseen row scores at most $2.5-2(0.4)=1.7$, below both retained scores, so we can stop after two rows.

The optional \texttt{stop\_when\_exact} setting implements this check with a rounding margin and keeps score ties alive. With candidate target zero, C stops when the bound proves the answer or when it reaches the root. A positive target can still stop approximately. The proof covers opened clusters; routing may exclude a global result.

The query sum and prefix minima take $O(d+x)$ setup work and $8x+8$ named query bytes, with constant work per later bound check. They add to $T_{\mathrm{key}}$ and $T_{\mathrm{ranges}}$, but do not change the stored index.

We can test this stopping logic mathematically. Let $\tau_q^*$ be the true $K$th score in the opened set, and $y_q$ the deepest stored prefix whose unseen bound is below it, using the code's rounding margin. Set $y_q=0$ if no positive depth qualifies. With no candidate-count stop, a walk starting at $x$ ends at
\[
 \boxed{\ell_q=\min(x,y_q),\qquad L_q=x-\ell_q+1.}
\]
Every true top-$K$ row must lie in a prefix with such a bound. Scoring that range therefore supplies the score needed to stop there. Starting deeper than $y_q$ adds lookups before reaching the same range; starting shallower may score more rows. The reference score is used only for this offline prediction. Actual search uses the scores it has found.

\subsection{Choose each method's settings}
The local conditions above hold routing fixed so we can understand one change at a time. In the final comparison, each method can choose different clusters and probes. Its routing time then changes too, so we compare complete queries rather than cancelling $T_0$.

For method $m$, let $\Theta_m$ be its tested settings and $\theta$ one complete choice. We select
\[
 \boxed{\theta_m^*=\underset{\theta\in\Theta_m}{\operatorname{argmin}}\,
 T_{m,\mathrm{measured}}(\theta)}
 \quad\text{subject to}\quad
 \overline R_m(\theta)\ge\rho,\quad
 M_{m,\mathrm{process}}(\theta)\le B_{\max}.
\]
$T_{m,\mathrm{measured}}$ is median whole-query time, $\overline R_m$ average recall, and $M_{m,\mathrm{process}}$ the recorded process-memory peak. The same dataset, query vectors, score, reference IDs, recall target and memory allowance apply to every method.

\begin{tabularx}{\linewidth}{@{}lYY@{}}\toprule
Method & Settings to vary & What must improve\\\midrule

\end{tabularx}
\end{center}
B establishes a measured advantage only if $T_B(\theta_B^*)<T_A(\theta_A^*)$ under those constraints; C must meet the same comparison. These are the best settings we tested, not a proof of the best possible configuration.

A larger RAM allowance can admit an index that did not fit before. It does not by itself remove bitmap passes or prefix lookups from an index that already fits. The next section therefore shows both the selected timings and the work counts behind them.
