\section{Deriving Optima}
For each prepared pool and result count $K$, we want the lowest whole-query time that meets the recall and RAM limits. The Experiment section declares the unchanged inputs, parameter grid and limits.

\subsection{Original method}
A reference document in the router's fifth cluster is scored when we open $P\ge5$ clusters. Let $C$ be total clusters, $n_q$ the query count, $K$ the result count and $\rho$ the required average recall. Write $s_{qi}^{(C)}$ for the cluster rank of reference result $i$ for query $q$. The smallest probe count meeting the target is

\[
 P_A(C,\rho)=\min\left\{P:
 \frac{1}{n_qK}\sum_{q=1}^{n_q}\sum_{i=1}^{K}
 \mathbf 1[s_{qi}^{(C)}\le P]\ge\rho\right\}.
\]
The indicator $\mathbf 1$ counts an ID when its cluster is open. We increase the cutoff if it splits tied centroid scores, repeating until no query has a tie across the boundary. Every method receives the same probe choices for a comparison. A one-cluster scan provides an exhaustive reference.

These ranks require actual queries, centroids and document assignments. Document and cluster counts alone cannot determine the cutoff. We calculate it separately for each declared $K$ using all cached queries.

For a conditional derivative, suppose clusters are equal and $P$ stays fixed. Let $\alpha$ be routing time per centroid, $\beta$ time per full score and result update, and $T_{\rm fixed}$ the setup and final sorting time held constant here. With $N$ documents,

\[
 T_A(C)\approx T_{\rm fixed}+\alpha C+\beta NP/C,\qquad
 \frac{dT_A}{dC}=\alpha-\frac{\beta NP}{C^2},\qquad
 C^*=\sqrt{\frac{\beta NP}{\alpha}}.
\]
Setting the derivative to zero gives $C^*$. At fixed recall, however, $P_A(C,\rho)$ can change with $C$, so this is only a conditional balance. We compare allowed cluster counts using actual sizes and probe choices.

\subsection{Bitplanes}
A 6400-document mask occupies 100 words. Avoiding 100 of the remaining scores saves 100 full-score calculations but adds 100 split-word visits. For $n$ documents, let $W=\ceil{n/64}$ be mask width, $\Delta F$ scores avoided, $a_B$ time per score and result update, and $b$ time per split-word visit. With added queue and final-mask time $\Delta T_{\rm other,B}$, splitting helps when

\[
 \boxed{\Delta F\,a_B>Wb+\Delta T_{\rm other,B}.}
\]
The saved time must exceed the added work while preserving the required recall. Suppose every cut halves one followed set and other branch costs stay fixed. After $j$ cuts, about $n2^{-j}$ rows remain, giving

\[
 T_B(j)\approx T_0+jWb+n2^{-j}a_B+T_{\rm other,B},\qquad
 j^*=\log_2\!\left(\frac{n\ln(2)a_B}{Wb}\right).
\]
Here $T_0$ is routing, common setup and final sorting time. Differentiating gives the candidate depth $j^*$; $\ln$ denotes the natural logarithm. Real cuts may remove no rows, and waiting branches add work, so we test the declared leaf sizes and node budgets rather than treating $j^*$ as a recall guarantee.

A node budget counts visited sets, including leaves. A leaf limit at least as large as a cluster lets us score it immediately. B receives all of A's routing choices, but its local limits can lose additional reference IDs. We therefore record the work counts and check the returned IDs.

\subsection{Backward Walk}
Alongside $C$ and $P$, we choose starting depth $x$ and candidate target $M$. With $h$ stored key bits, $0\le x\le h\le\min(d,32)$; full scores use all $d$ document bits. A deeper start selects fewer or the same rows, but may need more widening steps.

Let $F_A=\sum_{c\in\mathcal O}n_c$ count opened rows. Under independent, equally likely signs, a fixed prefix of depth $x$ would contain $F_A/2^x$ rows on average. For $M>0$, matching this count to $M$ gives $x\approx\log_2(F_A/M)$, with $F_A\approx PN/C$ if clusters are equal. That is a row-count estimate, not a prediction of reference membership or adaptive stopping. We check actual counts and recall for the declared settings.

At fixed routing, widening grows the scored set, so full-score recall cannot decrease. It adds new scores and range checks, with two binary searches per cluster at each nonzero depth. A zero target reaches depth zero, whose whole-cluster range needs no binary search.

In the three-row example, C avoids one of A's three scores but performs four binary searches and builds a query key. Using the previous section's time terms, it saves time when

\[
\boxed{F_Aa_A-F_Ca_C>
 T_{\rm key}+2L_+t_b\sum_{c\in\mathcal O}\log_2(n_c+1)+T_{\rm ranges}.}
\]
$F_C$ counts C's scores; $a_A$ and $a_C$ include scoring and result updates. $T_{\rm key}$ builds the query key once, $L_+$ counts nonzero depths, $t_b$ estimates comparison time, and $T_{\rm ranges}$ covers range bookkeeping. Whether the inequality holds depends on measured costs and the required recall.

\subsection{Comparison}
I keep the collection, embedding model and code length fixed for this comparison. For method $a$, let $\Theta_a$ be its tested settings and $\theta$ one choice. $T_{a,\rm measured}$ is median whole-query time, $\overline R_a$ average recall, and $M_{a,\rm process}$ the reported process-memory bound. With required recall $\rho$ and RAM limit $B_{\max}$ in bytes, we choose the qualifying setting with the smallest time:

\[
 \theta_a^*=\underset{\theta\in\Theta_a}{\operatorname{argmin}}\;
 T_{a,\rm measured}(\theta)
 \quad\text{subject to}\quad
 \overline R_a(\theta)\ge\rho,\qquad
 M_{a,\rm process}(\theta)\le B_{\max}.
\]

We retain failed settings and repeat selected ones in fresh processes. The comparison is limited to the declared grid.


A larger collection does not automatically make B faster. The full-score term grows with the number of opened documents, but each dense mask pass grows with that number too. If B needs many alternative branches to preserve recall, those mask passes can cost more than the scores they avoid. Larger collections can also change how much pruning is possible, so we measure the work at the tested settings instead of assuming that the two latency curves must cross.
