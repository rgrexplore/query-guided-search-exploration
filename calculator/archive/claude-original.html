Nanoseconds per query

Documents are binary-quantised to D sign bits. A query has to return the top 100 by score against those codes. Three ways to do that, priced in operations, milliseconds and index memory. Every constant is fitted to measured runs and shown at the bottom; change anything on the left and the numbers update.

RAM available for the index. Any configuration needing more is marked over budget and excluded from the sweep below.

Clustering — shared by all three

How many clusters each query visits (nprobe in FAISS). More probes means higher recall but more documents read. The true nearest neighbour often sits in a cluster you did not probe — that is the missed-cluster error.

Bitplane branching only

A node stops splitting once it holds this many documents or fewer; those documents are then scored one by one. Example: at 32, a cluster of 1,000 splits until each node holds 32 or fewer. Smaller leaf size = more splits (more bitplane work). Larger = more documents scored.

Hard cap on how many nodes the search expands before it stops and returns what it has. This is the node_budget option in the C++ index. Lower is faster but costs recall.

Walk backwards only

Documents are indexed in a hash table by this many of their sign bits. More bits ranks better but there are exponentially more keys to enumerate.

Enumerate keys until this many candidates are found, then score them exactly and keep the top 100.

A hash probe that misses cache costs roughly 80–100 ns; one that hits costs a few ns. 10 ns assumes most probes hit cache.

Choosing a configuration

Fix the corpus size, code length and memory budget, then sweep every combination of partition method, cluster count, probes, leaf size, node budget and key length. Each memory-feasible configuration is one point. What an engineer actually picks is the lowest point on their recall line.

Index memory

Latency is only half the story. Bitplane branching stores a transposed second copy of the codes, and walk backwards stores a hash table. Sizes at your current settings.
