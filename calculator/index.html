Search grid and what “best” means

Clusters: 1 and 2⁶, 2⁸, …, 2²⁰; probes: powers of two up to all clusters. B: leaf sizes 32, 128, 512 and node budgets 128, 2,048, 32,768 or unlimited. C: 8, 12, 16, 24, 32, 48, 64-bit keys and seven candidate targets up to the whole corpus.

These are the best estimated settings in this finite grid. A missing result means no grid configuration meets the modeled target and memory check; it does not prove the method cannot reach that recall. All configurations are retained in the CSV, including RAM rejections.

Normal score correlations and cluster loads are assumptions transferred from a small, reported experiment. A change in those assumptions can change the winner. The graph is a way to choose experiments, not evidence for a production SLA.

Memory during a query

Index memory persists between queries. Scratch memory is used while searching. A conservative frontier bound and the runtime reserve are included in the RAM check—not just the stored codes.

Why a dense lookup table grows so quickly

A sparse hash table stores occupied keys plus postings. A dense table allocates an offset for every possible key, including empty ones.

Recall checked on the same ground truth

Controlled random data and cached Nomic embeddings. Ground truth is exact full 256-bit scoring for every method. Correlation is estimated on 16 queries and checked on 16 different queries. C's measured recall does not imply a measured hash-search latency.

The recall formulas, with their assumptions

Binary score: S(q,b) = Σ qᵢbᵢ = Σ |qᵢ| − 2Σ |qᵢ|·1[bᵢ ≠ sign(qᵢ)]. Full-key search in increasing total penalty is exact if it finishes the top-100 boundary tie.

Measured recall@100: exact top-100 documents found ÷ 100. Use the same full score and row-ID tie order for every method.

Prefix score: T = Σᵢ≤h qᵢbᵢ. For independent equally likely binary documents, Var(S) = Σqᵢ² and correlation(T,S) = √(Σᵢ≤h qᵢ² / Σqᵢ²). This is a variance statement, not a guarantee about trained embeddings.

Population recall: P(full score is in its top-100 tail AND prefix passes) / P(full score is in its top-100 tail). The normal approximation estimates this using score correlation; the table shows its error on actual recall.

Empty-key count: V(τ) counts flip sets with total |query| penalty ≤ τ. Under uniform independent keys, expected candidates = N·V(τ)/2ʰ. For real correlated bits this can fail badly. The study measures candidates and counts V separately.

Matryoshka: useful prefixes are learned; coordinates are not sorted by query magnitude. The 80% prefix-variance case is constructed, not a claim about Nomic. Original paper.

What the original recall checks measured

The supplied router256.py uses top-100 float scores at 256 dimensions. shortcode.py uses float cosine at 768 dimensions. Our scaling CSV uses weighted binary top 100. These are different ground truths.

The new recall model consistently describes a hypothetical full-score distribution. It averages over the entire top-100 score tail. It does not claim that the imported observations validate it.

For C, flip sets are counted by quantized weighted penalty. A Hamming-radius formula would count all bit mistakes equally and would be a different algorithm.
